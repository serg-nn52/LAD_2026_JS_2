Сильные стороны: сделаны все 14 задач, у каждой — подписанный вывод «Задание N». №1.2 — аккумулятор-массив, как и задумано. №2.4 — переиспользована sortDesc из №2.3: верная мысль. №3.1, №3.3 — по эталону. №4.1 — сначала сравниваются длины. №4.3 — повторы отсекаются через includes, порядок первого массива сохраняется. №4.2 — rest-параметр и for…of, как требует условие. Переменные везде объявлены через let — в ДЗ №5 это было главным замечанием, здесь его нет.

№2.3 — исходный массив меняется: в условии прямо сказано: исходный массив не должен измениться. А sort сортирует массив на месте и возвращает тот же самый массив:

const digits = [3, 1, 4, 1, 5];
sortDesc(digits);
console.log(digits); // [5, 4, 3, 1, 1] — исходный массив испорчен

В твоём примере массив создаётся прямо в вызове, поэтому ошибку не видно. Сначала копия, потом сортировка:

function sortDesc(digits) {
  return [...digits].sort((a, b) => b - a);
}

В №2.4 эта ошибка не проявляется только потому, что concat уже создаёт новый массив.

№2.4 — формат строки: по заданию цифры идут через пробел: "9 5 4 3 2 1 1". У тебя join(', '), получается "9, 5, 4, 3, 2, 1, 1". Нужно join(' ').

№1.3 — граница цикла: k <= arr.length — на последнем шаге берётся arr[arr.length], а такого элемента нет: это undefined, и arr[i] + undefined даёт NaN. Сейчас NaN === 7 просто ложно, поэтому ответ верный, но это выход за пределы массива. Последний индекс — arr.length - 1, условие — k < arr.length.

— №3.2: counter всегда равен i + 1 — отдельная переменная не нужна. Проверка на пустой массив тоже лишняя: для [] цикл не выполнится ни разу и сработает return -1 в конце. Вся функция — цикл и два return.
— №4.2: цикл, который копирует numbers в newArr, не нужен: rest-параметр уже массив — сразу for (const num of numbers).
— №4.1: else после return false не нужен — если длины разные, функция уже вышла.
— №4.3: внутренний цикл по arr2 заменяет arr2.includes(arr1[i]) — ты и так используешь includes для повторов.
— Имена newArr и arr в пяти функциях ничего не говорят о содержимом. Лучше lengths, pairs, triples, result.

Новокшонова Наталья Сергеевна · ДЗ №6 · index6_natalia.js

Сильные стороны: сделаны все 14 задач, к каждой — свой пример и вывод из терминала. №1.2 — аккумулятор-массив, а первый шаг явно выделен проверкой acc.length === 0: читается без подсказок. №1.3 — j = i + 1, пары не повторяются. №2.3 — копия через slice() перед sort, исходный массив не меняется. №4.2 — rest-параметр, for…of и вызов через spread sumEven(...numbers). №4.3 — решено циклами, повторы отсекаются флагом exists, порядок первого массива сохраняется.

№4.1 — сравнивается только первый элемент: return true стоит внутри цикла, поэтому функция выходит уже после первой итерации. Если первые элементы совпали — сразу true, остальные не проверяются:

isEqualArrays([1, 2, 3], [1, 2, 4]); // true, а должно быть false
isEqualArrays([], []);               // undefined — цикл не выполнился, return не сработал

В твоём примере массивы одинаковые, поэтому ошибку не видно. return true нужно перенести за цикл: «все элементы прошли проверку — значит, массивы равны». Ошибку легко пропустить из-за отступов: когда закрывающие скобки выровнены, сразу видно, внутри цикла строка или после него.

for (let i = 0; i < arr1.length; i++) {
  if (arr1[i] !== arr2[i]) {
    return false;
  }
}
return true;

№2.2 — массив снаружи функции: const result = [] объявлен до функции, поэтому каждый вызов дописывает тройки в один и тот же массив:

getTriples("hello"); // ["hel", "ell", "llo"]
getTriples("abc");   // ["hel", "ell", "llo", "abc"] — остались тройки от прошлого вызова

Функция должна создавать результат заново при каждом вызове — перенеси const result = [] первой строкой внутрь getTriples, как ты сделала в №3.1 и №3.3.

Мелочи:
— №1.3: вывод в комментарии — [[0, 7], [0, 7], [1, 6], [2, 5]], а код (верно) возвращает [[0, 7], [1, 6], [2, 5], [3, 4]]. Вывод стоит копировать из терминала после последней правки.
— №3.2: count всегда равен i + 1 — отдельная переменная не нужна: return i + 1.
— №4.3: когда значение нашлось во втором массиве, перебирать его дальше незачем — подойдёт break, а без ограничения «только циклы» оба внутренних цикла заменяет includes.
— №2.4: sortDesc из №2.3 можно переиспользовать: sortDesc(arr1.concat(arr2, arr3)).join(" ").
