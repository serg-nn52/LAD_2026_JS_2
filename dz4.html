№2.1 — имя функции: getNumEqua — опечатка (Equal), а префикс get обещает «получить значение». Для функций, отвечающих «да/нет», принят префикс is/are: areNumbersEqual / isEqual.

№2.4 — странный способ вернуть true/false: return 1 === 1 и return 1 === 0 работают, но это обходной путь — true и false пишутся напрямую. А ещё короче — вернуть само условие, как ты сделал в №2.2. Плюс имя по заданию — isNumberInRange, у тебя isNumberInRang:

function isNumberInRange(num) {
  return num > 0 && num < 10;
}

Блау Борис Станиславович · ДЗ №4 · homework4_blau.js

Сильные стороны: к каждой задаче записаны тестовые значения и ожидаемые ответы. №1.4 через switch с return в каждом case и default на ошибку — чисто. Задание 3 сделано отлично: getDigitsSum переиспользуется в №3.2 и №3.3 (это и есть ключевой навык ДЗ — композиция), №3.2 оформлен функцией с параметром maxYear, №3.3 через while. №4.1 — стрелочная функция с split → reverse → join.

№1.3 — порядок операций (главный подвох задачи): num1 - num2 / num3 без скобок сначала делит, потом вычитает: для (5, 6, 7) выходит 4.14 вместо -0.14, для (100, 9, 3) — 97 вместо 30.33. Твой же ответ «97» это и показывает: 100 − 3. Нужно (num1 - num2) / num3. И у функции нет параметров — она читает глобальные переменные, а аргументы при вызове игнорируются:

function subtractAndDivide(a, b, c) {
  return (a - b) / c;
}
console.log(subtractAndDivide(100, 9, 3)); // 30.333…

№2.2, 2.3, 2.5 — функции без параметров: function isNumNegative() объявлена без параметра и внутри читает внешнюю num. Вызов isNumNegative(num) «работает» только потому, что глобальная переменная случайно называется так же. Передай функции, например, isNumNegative(-7) при num = 4 — получишь false. Функция должна работать только с тем, что ей передали: function isNumNegative(num) { … }.

№2.2 — не та задача: по условию функция принимает два числа и проверяет, что их сумма больше 10. У тебя проверяется одно число. Плюс имя isNumberLessThenTen говорит «меньше» (и Then → Than), а код проверяет «больше»:

function isSumGreaterThan10(a, b) {
  return a + b > 10;
}

№2.4 — границы: по условию число больше нуля и меньше 10, границы исключены. У тебя num >= 0 && num <= 10 → для 0 и 10 возвращается true Твой тест «10 → True» как раз показывает ошибку. Нужно num > 0 && num < 10, а имя по заданию — isNumberInRange.

№2.1 — имя функции: trueOrFalse описывает тип ответа, а не вопрос. Любая функция-проверка возвращает true/false — важно, что она проверяет: areNumbersEqual / isEqual.

Мелочи:
— if (условие) { return true; } else { return false; } (№2.1–2.5, №4.1) — можно вернуть само условие: return num1 === num2;.
— №1.1: Square с большой буквы — так принято называть классы/конструкторы; функции — с маленькой: square / getSquare.
— №3.2: в комментарии последний год указан как 2019, но 2+0+1+9 = 12. Последний подходящий год — 1930, всего их 148.

№4.1 — палиндром ломается на латинице: идея очистить строку (регистр, пробелы, знаки) — отличная, но регулярка /[^а-я0-9]/g удаляет все символы, кроме кириллицы и цифр. Для 'hello' строка очищается до пустой, '' === '' → true Добавь латиницу в диапазон:

const isPalindrome = (str) => {
  const cleaned = str.toLowerCase().replace(/[^a-zа-яё0-9]/g, '');
  return cleaned === cleaned.split('').reverse().join('');
};
isPalindrome('hello'); // false
isPalindrome('noon');  // true

Сильные стороны: все функции возвращают верные значения, в том числе на краевых случаях. Имена — по смыслу: sumOfTwo, subtractAndDivide, isEqual, isSumAbove10, isNegative, isNumberInRange, isEven, getDigitsSum. №1.3 — со скобками. №1.4 — проверка диапазона вынесена в начало функции. №3.2 — функция findYears(year1, year2) с параметрами диапазона и переиспользованием getDigitsSum, ровно 148 годов. №3.3 — цикл до однозначного числа (942 → 6, 12345 → 6). №4.1 — палиндром написан вручную через сравнение символов с двух концов: это сложнее эталона и работает верно (noon, racecar, a, пустая строка → true; hello, abca → false).

№1.4 — дни недели на английском и снова case (num = 1): по условию функция возвращает день недели на русском. Кроме того, повторилась ошибка из ДЗ №3: case (num = 1) — это присваивание, а не сравнение. Сейчас работает случайно: switch запоминает исходное значение, а каждый case перезаписывает num и сравнивает с результатом присваивания. В case пишется только значение:

switch (num) {
  case 1:
    return 'Понедельник';
  case 2:
    return 'Вторник';
  // …
}

А ещё короче — массив: const days = ['Понедельник', …]; return days[num - 1];

№2.2, №3.2 — переменные без объявления: temp = num1 + num2 и target = getDigitsSum(i) записаны без let/const. В обычном режиме JS молча создаёт глобальную переменную, которую видит и может испортить любой код. В строгом режиме ('use strict', ES-модули, классы) это ошибка: ReferenceError: temp is not defined. Любую переменную объявляй: const sum = num1 + num2;. В №2.2 её можно вообще убрать: return num1 + num2 > 10;.

Мелочи:
— №2.1: num2 - 3; — опечатка, вместо = стоит -. num2 осталась 7 от №1.3, поэтому проверка isEqual(7, 7) случайно вывела true. Сама функция верная.
— №2.4: в проверке вызвана isNegative(num1) вместо isNumberInRange(num1) — выведенный false не про эту задачу. Сама функция верная: 5 → true, 0 и 10 → false, верно.
— №2.1–2.5: if (…) { return true; } else { return false; } — можно вернуть само условие: return num % 2 === 0;.
— №1.1: powerTwo понятно, но привычнее square / getSquare; №4.1: функция-проверка — isPalindrome, а не palindrome.
— №4.1: отладочные console.log внутри функции лучше убрать — функция должна только возвращать результат. И две ветки (чётная/нечётная длина) делают одно и то же: хватит одного цикла for (let i = 0; i < Math.floor(str.length / 2); i++).
